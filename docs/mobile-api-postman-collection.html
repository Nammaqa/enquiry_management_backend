NammaQA Mobile Application API Reference

Complete Postman Collection, Authentication Flow & Endpoint Specifications
Base URLs: {{baseUrl}}/api or {{baseUrl}}/api/v1 (both prefixes are supported).
Postman File: docs/mobile-api-postman-collection.json (Directly importable into Postman).
Authentication: Public endpoints require no header. Protected endpoints require Authorization: Bearer {{token}}.
Email Verification Status: Fixed & active. Sends HTML OTP codes directly to user emails using Google Workspace SMTP.
Mobile App Developer Quick Note: During signup, a 6-digit OTP is automatically sent to both the student's Email and WhatsApp/SMS. The student enters this 6-digit code on the mobile app's verification screen, which calls /api/mobile/auth/verify-otp with { email, otp_code } to complete registration and obtain their authentication token.

1. Authentication & Email Verification APIs

POST /api/mobile/auth/signup Public Dual Delivery (Email + Phone)

Registers a new student account in the enquiry system and sends a 6-digit verification code to the student's email and phone number.

Request Headers: Content-Type: application/json
Request Body: 
{
  "fullName": "John Doe",
  "email": "johndoe@example.com",
  "phone_number": "9876543210",
  "password": "Password@123"
}
Success Response (200 OK): 
{
  "message": "OTP sent successfully to your email and phone",
  "deliveredTo": ["email", "phone"],
  "student": {
    "id": 45,
    "name": "John Doe",
    "email": "johndoe@example.com",
    "phone_number": "9876543210"
  },
  "enquiryId": 45,
  "reference_id": 12,
  "expiresIn": "10 minutes",
  "next": "Verify OTP using /api/mobile/auth/verify-otp endpoint"
}
POST /api/mobile/auth/verify-otp Public Primary Verification

Verifies the 6-digit OTP code. Accepts either email or phone_number or student_id. Marks the account as verified (isSignupVerified = true) and issues a JWT session token.

Direct Route Alias: POST /api/mobile/auth/verify-email-otp
Request Body (Email Verification): 
{
  "email": "johndoe@example.com",
  "otp_code": "123456"
}
Alternative Request Body (Phone or Student ID): 
{
  "student_id": 45,
  "phone_number": "9876543210",
  "otp_code": "123456"
}
Success Response (200 OK): 
{
  "message": "OTP verified successfully",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "student": {
    "id": 45,
    "name": "John Doe",
    "email": "johndoe@example.com",
    "phone_number": "9876543210",
    "candidateStatus": "enquiry stage",
    "classroomEligible": false
  },
  "enquiryId": 45
}
POST /api/mobile/auth/resend-signup-otp Public

Generates a fresh OTP and resends it to the user's email and phone number.

Direct Route Alias: POST /api/mobile/auth/send-email-otp
Request Body: 
{
  "email": "johndoe@example.com"
}
Success Response (200 OK): 
{
  "message": "OTP resent successfully to your email and phone",
  "deliveredTo": ["email", "phone"],
  "data": {
    "student_id": 45,
    "email": "johndoe@example.com",
    "phone_number": "9876543210"
  },
  "expiresIn": "10 minutes"
}
POST /api/mobile/auth/login Public

Authenticates user. Supports two login modes: (1) Password Login, or (2) Passwordless OTP Login.

Option A: Email + Password 
{
  "email": "johndoe@example.com",
  "password": "Password@123"
}
Option B: Email + OTP Code 
{
  "email": "johndoe@example.com",
  "otp_code": "123456"
}
Success Response (200 OK): 
{
  "message": "Login successful",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "student": {
    "id": 45,
    "name": "John Doe",
    "email": "johndoe@example.com",
    "phone_number": "9876543210",
    "candidateStatus": "class",
    "batchId": 3,
    "classroomEligible": true
  },
  "enquiryId": 45
}
POST /api/mobile/auth/send-login-otp Public

Generates and delivers a login OTP to registered email or phone for passwordless login.

Request Body: 
{
  "email": "johndoe@example.com"
}
POST /api/mobile/auth/check-student-exists Public

Checks whether an account exists for a phone number or email before user signup.

Request Body: 
{
  "phone_number": "9876543210"
}
Success Response: 
{
  "message": "Account exists",
  "exists": true,
  "role": "student"
}

2. Student Classroom & Profile APIs

GET /api/enquiry-students/validate-token Auth Required

Validates stored session token on app startup.

Headers: Authorization: Bearer {{token}}
Response: { "valid": true, "user": { "id": 45, "name": "John Doe", "email": "..." } }
GET /api/enquiry-students/classroom Auth Required

Returns the student's current classroom status, batch details, assigned instructor, and package progress.

Headers: Authorization: Bearer {{token}}
Response: 
{
  "success": true,
  "classroom": {
    "student": { "id": 45, "name": "John Doe", "candidateStatus": "class" },
    "batch": { "id": 3, "batchName": "QA Batch 2026-A", "timing": "10:00 AM - 12:00 PM" },
    "instructor": { "id": 2, "name": "Jane Smith", "email": "instructor@nammaqa.com" },
    "package": { "id": 1, "name": "QA Automation Professional" }
  }
}
GET /api/enquiry-students/classmates Auth Required

Lists fellow peers and students enrolled in the same batch.

Headers: Authorization: Bearer {{token}}

3. Batches & Course Catalog APIs

GET /api/student-batches Auth Required

Returns all batches the authenticated student is assigned to.

Headers: Authorization: Bearer {{token}}
GET /api/student-batches/:batchId/details Auth Required

Returns full schedule, instructor profile, and subject breakdown for a specific batch.

Headers: Authorization: Bearer {{token}}
GET /api/packages Public

Returns course packages available for enrollment, including syllabus, duration, and subjects.

Query Parameters (Optional): ?domain=Testing
GET /api/packages/domains Public

Returns sorted list of domains (Testing, Development, Cybersecurity, AI/ML, etc.) for category filters.

4. Attendance Management APIs

POST /api/attendance/mark Auth Required

Student marks classroom attendance by submitting the dynamic token from the instructor's QR code.

Headers: Authorization: Bearer {{token}}
Request Body: 
{
  "batchId": 3,
  "qrToken": "eyJhbGciOiJIUzI1NiIsInR5c...",
  "latitude": 12.9716,
  "longitude": 77.5946
}
Success Response (200 OK): 
{
  "success": true,
  "message": "Attendance marked successfully",
  "attendance": {
    "id": 104,
    "studentId": 45,
    "batchId": 3,
    "status": "present",
    "timestamp": "2026-10-16T17:15:00.000Z"
  }
}
GET /api/attendance/student Auth Required

Returns the logged-in student's complete attendance summary and percentage.

Headers: Authorization: Bearer {{token}}

5. Assignments & Batch Materials APIs

GET /api/materials/batch/:batchId Auth Required

Returns all lecture slides, PDFs, notes, and study links uploaded for the batch.

Headers: Authorization: Bearer {{token}}
GET /api/assignment-responses/my-submissions Auth Required

Lists all assignments submitted by the authenticated student, including scores and instructor feedback.

Headers: Authorization: Bearer {{token}}
POST /api/assignment-responses Auth Required

Submits student assignment files (PDF, ZIP, DOCX) and comments.

Headers: Authorization: Bearer {{token}}, Content-Type: multipart/form-data
Multipart Form Data:
  • assignmentId: (Number) ID of the target assignment.
  • comment: (Text) Optional student comment.
  • files: (File) Document attachment(s).

Common Error Codes

HTTP Status Reason Sample Response
400 Bad Request Missing required fields (e.g. email, otp_code, password) or invalid format. { "message": "All fields (fullName, phone_number, email, password) are required" }
401 Unauthorized Invalid/expired OTP code, wrong password, or missing/expired JWT token. { "message": "OTP has expired. Please resend OTP." }
403 Forbidden Account not verified (isSignupVerified = false) or insufficient role permissions. { "message": "Account not verified. Please complete OTP verification during signup." }
404 Not Found Student, Batch, or Package does not exist. { "message": "Student not found" }
500 Server Error Unhandled database or SMTP delivery failure. { "message": "Server error", "error": "..." }
